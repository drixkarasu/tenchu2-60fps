# How the patch works

Target: Tenchu 2 (US, SLUS-00939). The in-mission engine is `TENCHU2\GAME.EXE`, loaded at `0x80012000` (SHA-1 `F6C70FFB2EF7564D1DBE4FF3AB4C1BF1321A081F`). All addresses below are RAM addresses in that executable. Function names are our own labels.

## Delivery: a guarded DuckStation cheat

`cheats/SLUS-00939.cht` is generated by `tools/build_patch.py`. It contains:

- **Patch code (1067 words) at `0x80600100`**, in DuckStation's 8 MB RAM expansion, which the game never uses: it only knows about 2 MB, and in 8 MB mode its stack sits near the top of 8 MB. Every word is written behind `D0600082 0000`. With 2 MB of RAM, that address mirrors into the BIOS kernel, which holds `0x3C1A`, so nothing is written.
- **91 game-code hooks.** Each one is written only if 8 MB RAM is present **and** the original 32-bit instruction is still in place (`D0600082 0000` / `A0aaaaaa original` / `90aaaaaa new`). DuckStation skips a failed conditional chain up to and including the first non-conditional line, so a failed check skips the write. This keeps the hooks out of other executables (the front-end `MENU.EXE`) and other game versions. They are re-applied automatically when `GAME.EXE` is reloaded.
- **Draw distance presets**, which write a factor (in quarters) to `0x80608204` behind the same 8 MB check.
- **VSync timeout fix**, two 16-bit patches with no 8 MB requirement.

## 60fps: one logic step, two drawn frames

The mission main loop (`Mission_MainLoop`) runs camera → actors → stage → tasks/HUD → flip, once per 30Hz step. Five calls in it are redirected:

| Call site | Original | Patch |
|---|---|---|
| `0x80064184` | `Camera_Update` (`0x80053AE8`) | **B1_CamHook**: runs the camera, stores the current and previous views, and applies the draw distance factor |
| `0x8006418C` | `Actor_UpdateAndDrawAll` (`0x8001C734`) | **B3_ActorHook**: updates all actors, then records each actor's root position and bone angles (previous/current) before drawing |
| `0x80064194` | `Stage_Draw` (`0x8004B95C`) | **B5_StageHook**: marks where stage packets end, for the replay |
| `0x800641C4` | `Task_RunAll` (`0x8003A384`) | **B1_PreLogic**: restores the real camera before game logic runs |
| `0x80064544` | `Frame_FlipAndWait` (`0x800171C8`) | **B1_Flip**: shows the logic frame, then builds and shows the extra frame |

**The extra frame (B1_Flip):**
1. Capture the packets of the finished frame that aren't characters or stage (HUD, map, tutorial text, particles), walking the ordering table (its size is read from the GsOT header, so the enlarged 8192-entry tables are walked fully).
2. Flip with the actor positions and poses blended halfway between the previous and current step (`B3_Flip0`).
3. Set the view to the real current camera, and draw actors with their *draw pass only* (entering `Actor_DrawAll` at `0x8001C79C`, skipping the update loop).
4. Run `Stage_Draw` with the tick forced odd (the sky spin only advances on even ticks), the `rand()` seed (`0x800CEA20`) saved and restored, and the extra-frame flag set (see below).
5. Replay the captured packets into the new buffer, in the same ordering-table buckets.
6. Flip again, restoring the game tick, so the extra frame never advances the game clock.

**Frame pacing:** `Frame_FlipAndWait` compares the vblank and hblank counters with "last" timestamps (`0x80084730` / `0x80084734`). After each patched flip these are reset, so the game never tries to catch up.

**Stage_Draw also runs game logic.** Its tail calls `FUN_80050604` (hazard damage checks, then light/fire effects `FUN_8004ED74` and stage objects `FUN_8004FFAC`), `FUN_8004D318` (object triggers and breakables), `FUN_800507A4` (object movement and timers) and `FUN_8004AECC` (music fade). On the extra frame:
- the logic-only calls are skipped;
- effects and objects are drawn, with their animation counters (`+0x14` in the 0x18-byte effect table at `*0x8008CFC8`, `+0x6A` in the 0x78-byte object table at `*0x8008CFC4`), the fire-jet hitbox slot (`0x800C46FE`) and the lightning timer (`0x8008CDA8`) saved and restored;
- the positional sound function `FUN_8001E858` returns immediately.

## VSync timeout fix

PsyQ's `VSync()` wait loop (`0x800699DC` in GAME.EXE, `0x80114BB0` in MENU.EXE) gives up after a fixed number of loop iterations rather than a fixed time (`sll a1,a1,15`). With an overclocked CPU, the loop finishes early, so cutscene timing that relies on it runs fast. The fix raises the limit (`sll a1,a1,22`). This also happens in the unpatched game when overclocked.

## Draw distance

The game keeps one distance value `D` at `0x8008CEC8` (in GTE depth / 16 units). The stage loader sets it per area. It is used for rendering (world-block range, model far clip, fog) and for gameplay (enemy activation, AI vision bands, sound falloff, projectile range).

- 13 `lui`/`lw`/`sw` pairs (stage loader and gameplay readers) are redirected to a copy at `0x80608200`, so gameplay keeps the stock value.
- Each step, B1_CamHook writes `stock × factor / 4` into `0x8008CEC8`, which now drives rendering only. It is capped at 4000 (64,000 units): GTE depth saturates at 65,535, so a larger `D` would never trip the per-vertex far-clip test and polygons beyond the GTE's range would be drawn with saturated depth and a wrong projection.

**Fog** is computed per vertex in the polygon builder `Model_DrawPolys` (`0x80018DB0`): colour index = base − (depth − fog start), looked up in a 256-entry colour table. The original fog is a fixed 256-unit band ending at `D`. The patch:
- keeps the stock fog start and stretches the band so it reaches full fog at the new `D`;
- shifts the 21 per-vertex depth instructions right by `k`, rewritten at runtime by B1_CamHook;
- makes the prologue call `B10_FogStart` (via `jalr t3`, since the function is a leaf) to compute the fog start in shifted units (s1) and unshifted units (s2);
- changes six per-polygon early-out compares to use s2. Their depth value is also the ordering-table index, so it cannot be shifted.

**Reach of the world and the fog.** The level is a grid of blocks 16,000 units wide. `FUN_8004A748` only considers a 4×4 window of blocks around the camera, two blocks ahead in the facing direction (table at `0x80082230`), and level streaming (`FUN_8004B020`) keeps only the 5×5 blocks around the player loaded. Geometry therefore ends 32,000–48,000 units ahead whatever `D` is. The fog end is not capped to this reach: capping it at about 32,000 units (tried in testing) made 3x and 4x look shorter than uncapped, so higher presets show the furthest blocks less fogged.

**Stage objects.** `FUN_8004FFAC` draws objects within ¾ of the per-stage range at `0x80081EF0 + stage×0x14` (16,000–24,000), and registers collision for them (`FUN_8004D094`, 64-entry table). The range check at `0x80050238` is replaced by `B15_Range`: objects are drawn out to that range × the draw-distance factor, capped at 30,000 units (offsets are 16-bit in the visibility test `FUN_8004E35C`). Objects beyond the original range are marked "far": they are unregistered from collision instead of registered (`0x80050334`), and the falling-object (`FUN_8004FBB0`) and object-fire (`FUN_8004E944`) paths skip them, so gameplay keeps the original range. Lights and fire effects (`FUN_8004ED74`) keep their original range.

**Ordering tables.** Polygons are sorted into the GsOT by depth (index = average SZ / 16, the same units as `D`). The stock tables have 2048 entries (`length` 11) at `0x80092AA8` and `0x80094AE8`, which covers depths up to about 32,768. That is fine for the stock `D` (at most 1500) but not for 2×–4×: far polygons were written past the end of the table, into its spare space (never drawn), into the other frame's table (drawn in the wrong place, for example an enemy showing through a wall), or past it. The tables are now 8192 entries at `0x806E0000` and `0x806F0000`. The GsOT setup in `GAME.EXE` init (`0x80017130`–`0x80017148`) is patched, and B1_CamHook re-applies it (with `GsClearOt`) if the init ran before the cheat did. The sky (drawn while `D` = `0x7FF`) gets an ordering bias of +4096 in `B10_FogStart`, so it sorts behind everything else rather than in front of geometry beyond its radius.

**GPU packet buffers.** Originally 2 × `0x14000` bytes at `0x80096AE8`. The second buffer ends exactly at the large-model vertex cache (`0x800BEAE8`). At long distances, an overflow corrupted the frame the GPU was still drawing, or the vertex cache, and showed up as "exploding" polygons. They are moved to `0x80640000` and enlarged to 2 × `0x50000`: 7 base addresses, 8 index→offset shifts, and 3 limit checks (two flip-time checks, plus the per-model budget check in `FUN_80018304`).

## Testing

`tools/timing_test.lua` runs in PCSX-Redux, with 8 MB RAM on and the interpreter CPU. It takes a save state, walks the player forward for 10 s unpatched, reloads, applies the patch (`tools/SLUS-00939_patch.lua`) and repeats the walk. It then compares the distance walked per logic step and the logic steps per second. A pass means the patch changes neither the game's speed nor its logic.

## Ideas for further work

- **2 MB support** (real hardware, other emulators). This needs space for about 4 KB of code plus tables inside the original memory map, and smaller packet buffers.
- **60fps animation for fire and smoke** (interpolated animation counters).
- **Lower CPU cost:** level-of-detail for distant world blocks, and less duplicated work in the extra frame.
